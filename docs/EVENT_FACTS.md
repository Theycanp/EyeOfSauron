# 事件证据图与自动事实投影

## 当前实现

`EventEvidenceRepository.read_event_evidence` 是后台事件历史的统一读接口。
SQLite 适配器在一个只读事务快照内读取事件、报道、Claim、支持/反驳证据、
Timeline 和由报道关联的通知元数据；不返回通知正文或投递错误。
最多返回 200 篇报道、200 个 Claim、1000 条 ClaimEvidence、200 条 Timeline
和 100 条通知，分别返回截断标记。时间线当前是从早到晚的有界前缀；
超过上限时不得把它描述为完整历史。

后台“查看事件历史与匹配依据”展示当前记录、有争议和已被更正状态，以及
证据原文和通知详情链接。没有 Claim/Timeline 时显示尚无结构化记录；
这不代表报道没有事实，也不代表自动抽取已上线。

财政部实体按国家命名空间区分。明确机构国别优先于来源地区；无国别的
通用 Ministry of Finance 仅可由准确的具体国家元数据限定，不能从
GLOBAL/EAST_ASIA 等大区推断。多个国家财政部门的比较报道不自动合并。

## 自动投影当前边界

schema 21 的事实任务按 Report 持久认领、租约过期重试，Argus 运行时异步执行
保守的确定性抽取。当前只识别少量审查过的明确表述；没有抽取到 Claim 不
代表报道没有事实。抽取失败最多重试五次，人工合并/拆分会在同一事务中解除
被移动报道的自动证据并重新排队。schema 22 的发生身份索引只接受受审查的
一手结构化锚点或 USGS 官方 ID，不靠标题猜测同一事件。

以下仍是后续实现契约，不能把已有事实投影称为完整事件推理：

1. 事实候选是纯函数输出，包含 subject、predicate、scope、value、unit、
   polarity、effective_at、原文证据位置及 extractor 版本。
   slot_key 表示“同一主体、谓词和范围”，claim_key 表示具体命题。
   裸数字、预测、回顾、含糊代词和无法确认范围的转述不生成确定事实。
2. 已有持久任务和原子写入；仍需独立的历史回填速率和失败任务管理界面，
   以及从合法保存的正文中抽取，而不只是标题、摘要。
3. 自动与人工产出已有 provenance；人工修复能重建自动衍生记录，遇到人工
   Claim 或人工关联报道的 Timeline 仍拒绝，需专门的人工事实迁移工具。
4. 同 slot 同值追加支持证据；异值不自动判为更正。只有明确更正/撤回，或
   审查过的领域单调更新，才 supersede；低层级报道不能覆盖一手事实。
   多来源分歧保持 disputed，不通过选择最高分来源来抹掉冲突。
5. 日报使用事实时冻结 Claim 与 Evidence 快照。旧日报不得读实时事实，
   AI 必须呈现争议而非替用户选边，继续使用合法事件编号引用。
6. 统一更新通知须与事实转换、outbox 同事务保存，并以
   event_key + update_kind + fact_signature + topic 去重。
   重复支持、转载、市场反应和社交热度只归档；首次一手确认、重大升级、
   明确更正等按确定性策略判断。dead/cancelled 不能永久阻断新事实。

## 发生身份

持久 event_key 是不可变容器；新增版本化发生签名索引绑定官方 occurrence ID
或有充分实体、类别、地点、发生时间锚点的描述。发布时间与发生时间分开，
未知保持未知。不能用金额/伤亡/严重度作为发生身份，否则更正会分裂事件。
缺少发生锚点的任意跨语言文章无法保证到达顺序无关，需保留待审查状态，
不靠降低全局相似度阈值掩盖不确定性。历史已有归属不自动重写。

## 验收矩阵

必须覆盖输入排列、跨批次、重启、租约过期、事务故障、跨语言、跨午夜和
迟到报道；同地独立灾害、同机构不同动作、同值佐证、明确更正与可信否认、
无明确更正的异值、二手不能覆盖一手、dead 重试、Claim-aware 人工修复，
以及旧日报证据和通知 ID 保留。新自动投影不是纯函数单测通过就算上线；
还须通过完整仓库门禁、PR 检查和生产只读回放验收。
